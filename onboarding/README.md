# Onboarding videos

Screen-recorded training videos for each role of Nutrikal ERP, generated by
scripts from a **local demo database** — never from the live site.

| Video | File | Length |
|---|---|---|
| Обзор — how the roles hand work to each other | `out/overview.mp4` | ≤ 90 s |
| 1. Търговец (sales) | `out/sales.mp4` | ~3–4 min |
| 2. Администратор (admin) | `out/admin.mp4` | ~4 min |
| 3. Производство (production) | `out/production.mp4` | ~3 min |
| 4. Developer | `out/developer.mp4` | ~1 min |

Every video has `<video>.bg.srt`, `<video>.en.srt` and `<video>.captions.json`
(the caption data, kept for a later voiceover). Bulgarian is burned into the MP4.
`out/report.json` lists problems noticed on the pages while recording.

## Regenerate everything

```sh
cd onboarding
npm install                       # once: playwright + ffmpeg-static
npx playwright install ffmpeg     # once: Playwright's video encoder (not a browser)
npm run onboarding:record
```

The run takes ~20 minutes. It resets the demo database, seeds it, checks it,
records all five videos and writes `out/`. Running it again gives the same result.

Other commands:

```sh
node scripts/record-all.mjs sales admin          # only these videos (they still reset first)
node scripts/record-all.mjs --no-reset production # keep the current demo database
NK_FAST=1 NK_SHOTS=1 node scripts/record-all.mjs  # quick trial at full speed, no MP4; screenshots in raw/<video>/shots
npm run onboarding:reset                          # only reset + seed the demo database
node scripts/serve.mjs                            # run the demo app on http://localhost:3100 to look around
```

**The order matters.** The videos continue from each other: sales creates the
order, admin confirms the payment and sends it to production, production makes
it, and the overview shows the result. Recording `production` alone needs a
database where the admin video has already run.

Under Git Bash on Windows, put `MSYS_NO_PATHCONV=1` before `node` commands.

## Editing the captions

All titles, chapter cards and captions are in [`storyboard.md`](storyboard.md),
in Bulgarian and English. Change the text there and run the recording again;
no code changes are needed. Do not change the `id` column.

## Why this never touches live data

- The app runs from a separate git worktree (`/.onboarding-app`, git-ignored)
  that has no `.env.local`. The recorder refuses to start if any env file is
  there, and it starts Next.js with every Supabase, Google Sheet and cron
  variable set to empty.
- With those values empty the app uses its local PGlite database
  (`onboarding/.data/pg`), built from the migrations and the demo seed.
  The real `import/opening_stock.sql` is **not** loaded.
- `lib/demo-data.mjs` replaces everything that could be real: company and bank
  details, user names and e-mails, client names and contacts, prices in the
  price list, and adds the fictional catalogue product `DEMO-101`. The daily
  Google Sheet sync is blocked.
- `scripts/check-demo.mjs` runs before every recording and stops it if it
  finds real-looking data (real items or suppliers, nutrikal e-mails, the real
  IBAN, sheet links, old client names).
- While recording, e-mail addresses on screen are masked.

## How it works

| Path | What it does |
|---|---|
| `scripts/record-all.mjs` | reset → check → start app on port 3100 → record each video → MP4 + SRT |
| `lib/app-server.mjs` | the worktree, the local-only checks, starting and stopping the app |
| `lib/demo-data.mjs` | the demo dataset |
| `lib/recorder.mjs` | Playwright with the installed Google Chrome, 1920×1080; cursor, click rings, highlight box, cards, caption cues |
| `lib/overlay.js` | the cursor dot, click ring, highlight box and e-mail masking injected into the page |
| `lib/card.html` | title, chapter and recap cards (Poppins / Montserrat, ink #222831) |
| `lib/stitch.mjs` | writes the SRTs and burns the Bulgarian captions in with ffmpeg (30 fps, H.264) |
| `videos/<role>.mjs` | one script per video |
| `lib/users.mjs` | the demo users; each video acts as its role |

Locally there is no login screen: the session is the demo developer acting as
the video's role. In the role videos the developer's "act as" switch is hidden,
because a real user of that role does not have it. Raw recordings
(`raw/`) and the outputs (`out/`) are not committed.
